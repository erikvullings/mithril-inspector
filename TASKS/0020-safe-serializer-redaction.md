## Context
REQUIREMENTS.md §7.4 and §15: attrs/state inspection needs a lazy, safe serializer — never unrestricted `JSON.stringify` — plus privacy redaction. Prerequisite for attrs/state views in the tree UI (0022).

## Acceptance Criteria
- Serializer handles, with unit tests for each (§7.4): circular references (labeled), functions, DOM nodes, symbols, bigints, Maps, Sets, typed arrays, Errors, Promises, throwing getters, Proxies, deep/very large objects.
- Lazy inspection: max initial depth, max entries per page, getters evaluated only on explicit user action, redaction hooks (§7.4).
- Redaction (§15): default key patterns (password, passwd, secret, token, authorization, cookie, apiKey, accessToken, refreshToken) case-insensitive; configurable `redact: { keys, replacement }`; per-component `setInspectorSerializer` (§14) applied before display.
- Privacy defaults enforced: values displayed locally only, never sent to the dev server, never persisted, never in DOM attributes, never console-logged (§15).
- Output is a serializable preview tree (protocol type) the overlay can render and expand incrementally.

## Implementation Notes
- Snapshots are read-only (§7.3); no attrs/state editing (§3.3 non-goal).
- Add the preview-tree types to `@mithril-inspector/protocol` (0008) as a minor addition.
- Getter evaluation must be wrapped in try/catch and marked as user-triggered in the protocol so the UI can show "(...)" affordances.

- 2026-07-15: task created from REQUIREMENTS.md conversion; no work started.
- 2026-07-17 claude-sonnet: Implemented via TDD across protocol + runtime:
  - `@mithril-inspector/protocol`: additive `PreviewNode` discriminated union (§7.4, minor addition per Implementation Notes) — `primitive`, `bigint`, `symbol`, `function`, `dom-node`, `error`, `promise`, `array`, `object`, `map`, `set`, `typed-array`, `getter` (deferred accessor, carries `path`), `circular` (back-reference `path`), `redacted` (carries `replacement`), `max-depth` (truncated-by-depth stub, carries `path`) — plus `PreviewPath`/`PreviewPathSegment` (`prop`/`index`/`map-key`/`map-value`) for incremental expansion. Every field is a plain JSON-safe value — no live object references anywhere in the tree, satisfying "serializable preview tree."
  - `packages/runtime/src/serializer.ts` (new): `createSerializer(options)` — pure, side-effect-free builder. `serialize(value)` builds the initial tree eagerly to `maxDepth` (default 2) / `maxEntries` (default 50) per container page; `expand(root, path, { offset? })` re-derives the live value at `path` from the current `root` and re-serializes fresh from depth 0 — used for getter evaluation, paging past `maxEntries`, and expanding past a `max-depth` stub, all through the same primitive. Circular-reference detection uses a per-call ancestor-path stack (`Map<object, PreviewPath>`, push before recursing into a container, pop in `finally`) so a true cycle is labeled but a shared sibling reference is not. Every property/getter/trap access is individually wrapped in try/catch (never a blanket top-level catch) so a Proxy trap or throwing getter degrades to an inline `error` node instead of aborting the whole subtree (§16). Getters (real accessor descriptors, detected via `Object.getOwnPropertyDescriptor`) are never invoked during `serialize` — only `expand` calls them, one at a time, itself wrapped in try/catch (Implementation Notes: "user-triggered... wrapped in try/catch"). `DEFAULT_REDACTION_KEYS` is the exact §15 list (password, passwd, secret, token, authorization, cookie, apiKey, accessToken, refreshToken); matching is case-insensitive substring (same semantics as the requirements doc's unanchored `/password/i` example). Design decision (documented in the runtime README): an empty/omitted `redactKeys` falls back to the defaults (redaction is never silently off), but a *non-empty* configured list *replaces* the defaults rather than merging — this mirrors the already-shipped `@mithril-inspector/vite` adapter's own replace semantics (`packages/vite/src/options.ts`, task 0013) so the two layers behave consistently. Default-pattern redaction is intentionally non-bypassable: it still applies to a per-component `setInspectorSerializer` hook's *output*, and `expand()` refuses to walk through (or land on) a redacted key/Map-entry — closing a getter/expand back-door that would otherwise let a click-triggered evaluation bypass the same-key redaction a plain read would have hit.
  - `packages/runtime/src/components.ts`: `ComponentRegistry.setSerializer`/`serializerOf` retyped from `unknown` to the new `ComponentDataSerializer` (`{ attrs?(attrs): unknown; state?(state): unknown }`, §14's documented shape); added `defOf(id)` (the tracked instance's original definition object, needed to look up its serializer by id).
  - `packages/runtime/src/runtime.ts`: builds one `Serializer` instance from `RuntimeOptions.redact` (already-existing config plumbing from task 0013); added `attrsPreview(id)`/`statePreview(id)`/`expandPreview(id, target, path, options?)` to `InspectorRuntime`, each running under a new `"serializer"` error-boundary feature (§16 — isolated from `"component"`/`"source"` failure counts) and returning `null` for an unmapped/hidden id. Each composes: raw `attrs`/`state` from `components.recordOf(id)` → the definition's custom `setInspectorSerializer` hook if any (via `components.defOf`/`serializerOf`, wrapped in try/catch — a throwing hook falls back to the raw value, §16) → `serializer.serialize`/`.expand`. `api.ts`'s exported `setInspectorSerializer` retyped to match.
  - Privacy defaults (§15) verified by inspection, not just by omission: no `console.*`, `fetch`/`XHR`, or storage API call anywhere in `serializer.ts`/the new `runtime.ts` code; nothing writes to DOM attributes (the serializer only *reads* the value graph, matching §7.3 "read-only snapshots" / §3.3 non-goal — no attrs/state editing anywhere).
